# 멀티에이전트 리뷰 파이프라인

이 폴더는 이 저장소용 서브에이전트 정의다. **오케스트레이터(사용자와 대화하는 메인 세션)**가
`coder`에게 구현을 시키고, 산출된 diff를 **리뷰어들에게 병렬로** 검토시킨 뒤, 반려 사유를 모아
`coder`에게 재지시한다.

## 에이전트 목록

| 에이전트 | 역할 | 실행 시점 | 도구 |
|---|---|---|---|
| `coder` | 구현/수정 | 매 작업 | 쓰기 가능 |
| `review-offline` | 폐쇄망·오프라인 규약 | **항상** | 읽기 전용 |
| `review-degradation` | 우아한 저하 | **항상** | 읽기 전용 |
| `review-safety` | 안전 게이트·3티어 | **항상** | 읽기 전용 |
| `review-korean` | 한국어·인코딩 규약 | **항상** | 읽기 전용 |
| `review-mcp-tooldesc` | MCP 도구 설명 품질 | `mcp_server/*_server.py` 변경 시 | 읽기 전용 |
| `review-com` | COM/Windows 세션 제약 | `office/outlook/pdf_server.py` 변경 시 | 읽기 전용 |
| `review-rag` | RAG 구성/서빙 경계 | `rag_*.py` 변경 시 | 읽기 전용 |
| `review-llmstudio` | llm_studio 저장·격리 | `llm_studio/**` 변경 시 | 읽기 전용 |

## 라우팅 (오케스트레이터가 판단)

1. 코어 리뷰어 4개(`offline`·`degradation`·`safety`·`korean`)는 **diff가 있으면 무조건** 병렬 실행.
2. 도메인 리뷰어는 **diff가 건드린 경로**에 해당하는 것만 실행.
   - `git --no-pager diff --name-only`로 바뀐 파일을 보고 위 표대로 라우팅.
3. 리뷰어는 서로 독립 → **한 메시지에서 Agent 도구를 여러 번 호출해 병렬로** 띄운다.

## 반려 루프

- 각 리뷰어는 `판정: PASS | REJECT`를 반환한다. REJECT면 `[파일:라인] 위반규약 — 문제 — 수정지시` 목록.
- 오케스트레이터는 모든 REJECT를 취합해 `coder`에게 "이 항목들 고쳐서 다시" 재지시한다.
- **재작업은 새 Agent 호출이 아니라 같은 coder를 SendMessage로 이어서** 문맥을 유지한다.
- 2~3회 반려 후에도 해소 안 되면 **사용자에게 에스컬레이션**(규약 충돌·요구 모호 등 판단 필요).
- 리뷰어는 **자기 담당 관점만** 본다. 담당 밖 문제는 지적하지 않는다(중복 반려 방지).

## 원칙

- 리뷰어는 코드를 **고치지 않는다**. 반려 사유만 낸다(읽기 전용 도구).
- 근거는 항상 `CLAUDE.md`의 어느 규약인지 인용한다.
- 확실하지 않으면 REJECT 대신 `권고`로 남긴다(과잉 반려 방지).
- 커밋은 오케스트레이터가 사용자 승인 하에만. coder/리뷰어는 커밋하지 않는다.
