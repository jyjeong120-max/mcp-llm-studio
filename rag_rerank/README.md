# rag_rerank — 리랭커 모델 반입 폴더

RAG 검색 서버(`mcp_server/run_rag_server.bat`)가 검색 결과를 **관련도로 재정렬**할 때
쓰는 **리랭커 모델**을 여기에 둡니다. 큰 파일이라 git에는 올라가지 않고(`.gitignore`),
이 README만 추적됩니다 — USB 등으로 반입하세요.

리랭커는 하이브리드(벡터+키워드)로 뽑은 상위 후보를 **질의-문서 관련도**로 다시 정렬해
정밀도를 올립니다. 특히 **한↔영 교차언어** 검색에서 상위 순서를 크게 개선합니다.

## 넣을 것

1. **리랭커 GGUF 1개** — 예: `bge-reranker-v2-m3-Q8_0.gguf` (다국어 크로스인코더 권장)
   - 이 폴더에 `.gguf`가 **딱 하나면 서버가 자동으로 선택**합니다.
   - 여러 개면 `run_rag_server.bat --rerank-model rag_rerank\<파일>.gguf`로 지정.
2. **`llama-server.exe`** — 보통 `rag_embed/`에 이미 두므로 여기 또 넣을 필요는 없습니다.
   (실행 파일은 `LLAMA_SERVER_BIN` > `rag_embed`/`rag_rerank`(하위 재귀) > PATH 순으로 찾습니다.)

## 동작

`run_rag_server.bat`(RAG 검색 서버)를 실행하면:

1. 리랭커 서버가 이미 떠 있는지 확인 → 있으면 그대로 사용
2. 없으면 이 폴더의 `.gguf`를 `llama-server --reranking -ngl 0`(CPU)으로 **백그라운드 자동 기동**
   (모델 로드가 MCP 연결을 막지 않게 별도 스레드로 띄웁니다)
3. 검색할 때 상위 후보를 재정렬 — 준비 전에는 RRF 순서로 저하했다가 준비되면 자동 적용
4. 서버가 내려갈 때 우리가 띄운 리랭커도 **함께 종료**

모델이나 실행 파일이 없으면 죽지 않고 **RRF 순서를 그대로** 씁니다(리랭크만 건너뜀).

## 참고

- 포트는 `RAG_RERANK_URL`(기본 `http://127.0.0.1:8002/v1`)에서 가져옵니다.
- 컨텍스트/배치 크기는 `RAG_RERANK_CTX`(기본 4096)로 조정 — 질의+문서 쌍이 물리 배치를
  넘으면 재정렬이 실패하므로, 긴 청크를 쓰면 이 값을 키우세요.
- 자동 기동을 끄려면 `run_rag_server.bat --no-rerank-server` (이미 떠 있는 서버만 사용).
